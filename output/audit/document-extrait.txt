EventiaEasy — Rapport de tests et envois WhatsApp
Application :
 
https://eventiaeasy.vercel.app/
Date des tests :
 31 octobre 2026
Document :
 rapport général et résultats des deux tentatives WhatsApp réunis.
Les constats décrivent la version testée le 31 octobre 2026. Aucun nouveau contrôle de l’application n’a été effectué
pour produire ce document.
1. Résultat général
Le parcours de création d’un brouillon, ajout d’un invité, génération d’une invitation, réponse RSVP, contrôle des entrées
et placement à table a fonctionné.
Les principaux problèmes constatés concernent la restauration de session, les liens du menu liés à l’événement actif, les
compteurs de l’en-tête et la galerie facultative. Les deux tentatives d’envoi WhatsApp ont échoué avec le code 132012,
y compris après ajout d’une photo.
2. Périmètre et méthode
Tests fonctionnels sur le site déployé, dans Chromium automatisé :
Ordinateur : 1440 × 1000 pixels.
Affichages mobiles simulés : 390 × 844 et 320 × 740 pixels.
Compte de test fourni par le propriétaire.
Contrôles publics, connexion, création d’un événement de test et parcours invité.
Deux envois WhatsApp ciblés, demandés explicitement par le propriétaire.
Aucun mot de passe ni identifiant de connexion n’est reproduit dans ce rapport. Les tests ne constituent pas une
validation exhaustive ni un audit de sécurité.

l’erreur 404.
EE-02 — Menu latéral conservant l’événement précédent
Priorité : P1, élevée.
Reproduction :
1. 
Se connecter avec un événement déjà sélectionné.
2. 
Créer un autre événement.
3. 
Comparer le lien « Invités » du menu et celui des onglets du nouvel événement.
Observé :
 dans la fiche de l’événement de test 
/dashboard/events/1000007
, l’onglet local « Invités » pointe vers
/dashboard/events/1000007/guests
. Le menu latéral et la navigation inférieure mobile pointent encore vers
/dashboard/events/1000005/guests
. Un décalage similaire a été observé pour les catégories et d’autres liens.
Impact :
 les deux navigations proposent des contextes différents. L’utilisateur peut passer involontairement à
l’événement précédent. Aucune donnée d’un événement préexistant n’a été modifiée pour vérifier ce point.
Attendu :
 synchroniser l’événement actif avec la route courante et la création d’un événement, ou rendre explicite le
contexte du menu. Une source commune d’identifiant devrait alimenter les liens concernés.
EE-03 — Compteurs restant à zéro après les ajouts
Priorité : P2, moyenne.
Reproduction :
 créer un événement, ajouter un invité, créer son invitation et enregistrer les entrées, sans quitter la fiche
de l’événement.
Observé :
 l’en-tête conserve « 0 invités », « 0 invitations » et « 0 présents », alors que les vues détaillées affichent un
invité, une invitation et trois personnes entrées. Le décalage persiste après un changement d’onglet dans cette fiche.
Attendu :
 actualiser les statistiques ou invalider leur cache après les opérations concernées. Distinguer clairement le
nombre d’invités du nombre de personnes, accompagnants compris.

4. Améliorations du parcours public
EE-05 — Appels à l’inscription ouvrant la connexion
« Commencer gratuitement » et « Créer mon espace » ouvrent 
/login
 avec « Bon retour parmi nous » et la connexion
active. L’inscription nécessite un clic supplémentaire sur « Créer un compte ».
Recommandation :
 ouvrir directement le formulaire d’inscription depuis ces deux appels à l’action. Conserver la
connexion pour « Se connecter ».
EE-06 — Récupération du mot de passe non proposée
Aucun lien ni bouton « Mot de passe oublié » n’est visible sur l’écran de connexion testé. Cela ne prouve pas l’absence
d’une procédure de support externe.
Recommandation :
 proposer une récupération autonome avec une confirmation qui ne révèle pas l’existence du
compte.
EE-07 — Navigation de l’accueil masquée sur petit écran
À 320 pixels de largeur, les liens « Fonctionnalités », « Comment ça marche », « Témoignages » et « Contact » sont
masqués dans l’en-tête. Aucun bouton de menu ne les remplace ; le seul bouton de l’en-tête est celui du thème. Le
contenu reste accessible par défilement.
Recommandation :
 proposer une navigation mobile permettant d’atteindre directement les sections.
EE-08 — Noms techniques de certains boutons
Sur les écrans publics, l’arbre d’accessibilité expose notamment le bouton de thème comme 
dark_mode
 et celui
d’affichage du mot de passe comme 
visibility
. Ces noms ne décrivent pas l’action en français.
Recommandation :
 utiliser des noms accessibles tels que « Activer le mode sombre » et « Afficher le mot de passe »,
adaptés à l’état, et masquer les icônes décoratives aux lecteurs d’écran. Le contrôle du nombre de personnes du RSVP
dispose, lui, de noms explicites.

9. Vérifications techniques recommandées pour WhatsApp
Le modèle utilisé attend un en-tête de type 
IMAGE
, tandis que les paramètres reçus ne correspondent pas à ce format.
La cause précise dans le code n’a pas été établie.
À contrôler :
1. 
Le modèle réellement sélectionné et le type d’en-tête approuvé.
2. 
La construction du composant d’en-tête 
image
 dans la demande WhatsApp.
3. 
L’identifiant de média ou l’URL d’image HTTPS fournis et leur accessibilité pour le fournisseur.
4. 
Le blocage explicite de l’envoi si un média requis manque ou est invalide.
5. 
La distinction entre le statut général d’une invitation, l’expédition par canal et la livraison effective.
Après correction, une nouvelle tentative devra vérifier l’envoi puis la livraison. Aucun succès d’envoi ni réception sur le
téléphone n’a été établi par les deux tests décrits.
10. Limites et priorités
Non vérifiés : scan physique avec caméra, livraison des emails, import Excel et ses erreurs, annulation et modification
complète d’événements, gestion des rôles, isolation entre organisations, paiements éventuels, concurrence multi-
appareils, réseau hors ligne, charge, accessibilité complète et compatibilité Safari/Firefox.
Priorités :
1. 
Corriger la restauration de session et la cohérence des liens de l’événement actif.
2. 
Corriger les paramètres d’en-tête image du modèle WhatsApp.
3. 
Actualiser les compteurs après chaque opération.
4. 
Traiter correctement une galerie facultative absente.
